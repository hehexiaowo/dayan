## 🗓️ 执行顺序与依赖

```
P0-A  ──→  P0-B  ──→  P0-C  ──→  P0-D
(骨架+DB)   (启动)     (登录+SM)   (前端+CI)
```

- **P0-C** 依赖 P0-B 的启动模块，登录接口需要业务模块 Service 实现才能注入
- **P0-D** 依赖 P0-C 的登录接口，前端登录页对接真实 API

## 🧰 全局约定（所有子计划共同遵守）

### Git 提交规范

中文 commit，Conventional Commits 风格：
- `feat(scope): xxx` 新功能
- `chore(scope): xxx` 构建/脚手架
- `docs(scope): xxx` 文档
- `refactor(scope): xxx` 重构
- `test(scope): xxx` 测试
- `fix(scope): xxx` 修复

scope 可以是：common / gateway / module-system / module-organ / starter-admin / web-admin / db / ci 等。

### 验证原则

- 后端骨架任务：`mvn -B -ntp -DskipTests install` 编译通过 + 模块元数据正确
- 业务逻辑任务：必须 TDD——先写失败测试 → 运行验证失败 → 实现 → 运行验证通过 → commit
- DDL 任务：MySQL 容器启动后 SQL 文件自动执行，校验 `information_schema.tables` 计数 = 127
- 前端任务：`npm run build` 通过

### 工作目录

仓库根 `F:/code/dayan`，所有模块直接置于根下，不引入 `dayan-server/` 中间层。

### 频繁 commit

每完成一个有意义的步骤即 commit，不积累大变更。
